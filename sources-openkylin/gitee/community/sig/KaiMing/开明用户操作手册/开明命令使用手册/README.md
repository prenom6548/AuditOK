# kaiming

kaiming 是一个用于在各种 Linux 发行版上分发桌面应用程序的框架。它是麒麟软件开发人员创建的，并作为独立的开源项目运行。

kaiming 是一个包管理器客户端，用于管理开明包格式应用的安装、卸载、运行、更新等操作。


## 术语

- **kaiming**：一个用于在 Linux 上构建、分发和运行沙盒桌面应用程序的系统。
- **kaiming 应用程序**：这些是用户通过`kaiming`命令或通过不同的 UI（如 GNOME Software 或 KDE Discover）安装的应用程序。
- **运行时**：也称为平台，这些是集成平台，提供 kaiming 应用程序工作所需的基本实用程序。

## 目标群体

kaiming可以被各种桌面应用程序使用，旨在尽可能与应用程序的构建方式无关。 也对编程语言，构建工具，工具包或框架不作要求。

虽然kaiming只能在Linux上运行，但它可以被针对其他操作系统的应用程序以及特定于Linux的应用程序使用。 应用程序可以是开源的或专有的。

kaiming提出的唯一技术要求是应用程序遵循少量的Freedesktop标准，以实现桌面集成。

## 传统软件包格式存在的问题

了解传统软件包格式存在的问题对于了解 kaiming 的存在非常重要：

- **系统与应用无明确界限**：传统deb/rpm软件包之间依赖关系错综复杂，没有明确的系统与应用的界限。会出现安装某个软件后，系统工作不正常问题。普通用户想要尝试一些新软件，还需要root权限安装，担心安全问题。
- **发行版碎片化，版本各不相同**：各种衍生的发行版非常多，采用的开发库版也不尽相同，开发库及版本碎片化问题严重。开发者需要为每个发行版打包软件，或者忽略大多数发行版仅支持几个主流发行版，消耗精力增加成本，无法专注应用本身的开发。这会导致延迟每次分发的进度。这使得Linux桌面成为供应商难以瞄准的平台，让操作系统领域难以快速创新。
- **兼容问题日益严重**：传统打包格式在设计之初，并没有关注兼容性问题。对解决软件的兼容性问题没有帮助。社区版维护者顾及应用兼容性，不敢及时跟踪上游版本进展。对于普通用户而言，会面临大量升级后某些软件无法使用了。

openKylin 开源社区致力于解决上述问题，让开发人员能够方便地从一个来源分发应用程序并针对整个 Linux 桌面。

## 使用kaiming的理由

与大多数系统包管理器相比，kaiming 具有一些主要优势：

- **应用隔离更兼容**：一次打包，到处发布。解决将应用软件与系统隔离开，根本上实现向后兼容。
- **多格式融合**：支持 Linux 存量应用、AppImage等多种格式应用的导入，统一管理。
- **细粒度权限管控**：支持应用间隔离和更细粒度的权限管控，提高安全性，保护用户在每个应用中的隐私。
- **安全治理**：逐步减少软件库的碎片化，跟踪修正基础库安全漏洞，让应用软件更健康。
