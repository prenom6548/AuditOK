## 会议纪要
### 讨论重点
- 启动基于 Milestone、Issue 和 PR 的三段式研发流程，以提升版本质量与开发有序性。
- 明确版本发布策略：当前阶段采用打 tag 方式，不维护长期分支，每个版本周期约三个月。
- 要求在版本验收最后两周停止合入新功能，集中进行 bug 修复与稳定性测试，确保零 bug 回归。
- 确定所有 PR 必须关联 Issue 并注明所属 Milestone，bug 修复需在测试框架中补充对应场景的测试用例。
- 规划 6 月 30 日为第一个正式版本发布节点，重点建立与 Linux 的对比性能基线，并支持普罗米修斯、K01百、国测等关键场景。
- 讨论了 VSOCK 性能优化的进展，确认当前存在卡死等问题需要逐步修复。
- 孙昊晟建议补充 DHCP 功能，郭伟康确认该需求对上层网络支持很重要。
- 明确了 Daily Test 对版本质量的关键作用，需增加性能回退告警机制。
- 会议讨论了 K01百项目中，用户版本强制开启 SELinux 后带来的安卓权限适配问题。
- 会议讨论了国测项目中 FVM 适配问题，确认问题源于签名证书不匹配，需替换正确证书后重新测试。

### 决议事项
- 正式启用基于 Milestone、Issue 和 PR 的研发流程规范，全体开发人员须遵守。
- 6 月 30 日作为首个正式版本发布节点，需完成验收测试并打 tag 发布。
- 所有缺陷和需求在版本验收前需全部关闭，实现零 bug 回归。
- 测试团队需制定验收计划，完成基础功能、集成场景、稳定性和安全的验收。
- 测试报告需随 release 说明发布，由测试团队负责归档。
- 由孙昊晟接替易书琪完成基于 tracepoint 的延迟测试脚本 PR，并将其迁移至 daily test 框架。
