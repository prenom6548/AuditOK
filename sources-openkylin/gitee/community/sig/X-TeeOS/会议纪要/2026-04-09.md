## 会议纪要
### 讨论重点
- Harness 测试框架已嵌入 fio 文件系统测试，并建立 ext4 性能基线，与 Linux 进行了对比分析。
- 上游 StarOS 主仓代码本周未有更新，需确认是否遗漏 dev 分支。
- 鼓励团队根据自身工作提炼创新点，积极申报专利，公司有培训材料和奖励。
- Kunit 与 Kselftest 的调研已完成，需进一步分析其测试场景是否被当前 Chakra-kernel 单元测试覆盖。
- CI 效率持续优化，多 Runner 并行后，主 CI 流程已从20分钟压缩至12分钟。
- eBPF 支持工作已梳理初步路线，建议先从性能分析（火焰图等）这一具体目标切入，不发散。
- 文件系统写入性能较差，需参考其他 Rust OS 实现，拓宽优化思路，优先从写入算法和 I/O 路径入手。
- 维多利亚监控（VictoriaMetrics）已在 Chakra 上测试，发现其内存占用约为普罗米修斯的 1/3，但存在配置不当导致数据丢失和内存异常增长的问题。
- 网络子系统性能测试（netperf）已开展，并成功修复了测试工具中关于时钟和队列的 Bug。
- 因上游 hypervisor 架构变更（走向全直通），需重新支持 GICD 虚拟化设备，以恢复双 Guest 启动能力。
- 小车摄像头出图问题卡在 DMA 内存分配，建议评估使用 STM32 绕开 USB 驱动难题，先保证流程跑通。
- 可信子系统讨论 TA 升级场景中 disk image 被覆盖导致安全存储数据丢失的问题，需设计增量升级方案。

### 决议事项
- 确定监控方案切换方向：不再使用普罗米修斯，后续改用兼容其协议的维多利亚监控。
- 成员挂起的 PR 应互相 review 后尽快合并，避免长期堆积。
- eBPF 工作初步目标是辅助文件系统进行性能分析，后续按此方向规划具体实现。
