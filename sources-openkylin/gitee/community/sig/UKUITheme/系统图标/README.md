# 图标主题

  在制作图标主题包时可以参考 [openkylin-theme](https://gitee.com/openkylin/openkylin-theme)主题包中的 icons/ukui-icon-theme`*` 部分目录中的内容。

  在参与制作一个全新的主题包前，不妨先从已有的主题包维护入手，这样更有助于你对系统主题包的了解。

## 图标主题相关规范

  在处理一套图标主题前，你需要对图标主题规范有一定了解:
  1. 图标和主题是在一组目录中查找的。默认情况下，应用程序应在$HOME/.ions、$XDG_DATA_DIRS/icons和/usr/share/pixmaps（按顺序）中查找。应用程序可以进一步将自己的图标目录添加到此列表中，用户可以扩展或更改列表（以应用程序/桌面特定的方式）。
  2. 图标文件必须是以下类型之一：PNG、SVG，并且扩展名必须是“.png”或“.svg”。“.svg”文件;
  3. 关于图标命名规范，图标名中不可以出现空格，不可以出现奇怪的符号;
  4. 图标主题目录中必须包含index.theme文件用于描述主题;

### 第三方应用图标规范：

  为了给第三方应用程序提供一个安装图标的位置，系统中应该始终存在一个名为 "hicolor" 的主题。

  如果没有指定主题，则要求开发者将 "hicolor" 主题添加到继承树中。当我们的自研应用存在于其他桌面环境时，应作为第三方应用，将我们的图标放在"hicolor"主题里。

  作为应用程序的开发者，为了在当前桌面环境菜单中正常显示，我们至少需要在hicolor中安装48x48尺寸的图标。安装在目录 $prefix/**share/icons/hicolor/48x48/apps** 中。为了更好的将图标显示（规避显示模糊的风险）以及表达>我们的设计语言，请将图标.svg格式，安装在 $prefix/**share/icons/hicolor/scalable/** 下。程序内所需要的其他图标以及线性图标，同样的，根据设计提供的图标尺寸放在hicolor中相应的尺寸目录下。


## 修改图标主题

  首先在修改openkylin图标主题中的图片时，请遵守openkylin对图标命名的规范[图标规范请参考这里](https://docs.qq.com/sheet/DTkRyUm5wVkVab1pN?tab=BB08J2&u=9487ce2cd5cb4d2cb525bda876ff13f7)，最基础的就是不向文件夹里乱添加图片。为了使用户在切换主题时每个图标都能生效，这是必须的。

  当你打开图片文件夹时，你可以看见很多按照规格排列的文件夹。是的，目录名称代表着目录内图片尺寸大小，当你得到一张.png切符合命名规范的图片想要替换到图标主题时，也请根据尺寸到相应文件夹以及相应类型下进行替换。请注意，scalable 目录下没有固定尺寸，因为此文件夹下的图片为.svg 类型，.svg类型图片没有固定大小，颜色也可以根据程序进行改变。

  目录下的 index.theme 文件是配置文件。如果你检查到明明对应文件夹里有图片却一直没有显示或者显示尺寸有错，那么可能是这里出错了。每个目录下的文件夹都会被此文件配置，如果有新增加的文件夹那么请一定要更新此配置文件，不然此文件夹下的所有内容将不会被调用。

  那么到底要如何正确替换图标呢？截止目前为止，此目录下有170+的文件夹，有超过2.7万张图片，寻找某一张图片的无疑是大海捞针。  
  方法一，在 /usr/share/application 目录下有对应的 .desktop 文件，打开对应软件的 .desktop 文件，可以看见 Icon 一行，后面所接内容为对应软件所使用图片名称； 
  方法二，清楚需要替换的图片是属于什么类型，直接在对应类型的文件夹下寻找；  
  这两种方法基本可以帮助你定位出错图片位置。当然，实在无法确认对应文件类型时就用排除法，删掉目标目录，如果图片显示被影响了，就说明图片在此文件夹下。 

  在图标主题下有很多相同的图标，那么我们该如何控制他们同时切换呢？  
  这个时候就用到了软链接，因软链接生成的图片会跟着父级图片进行改变,很大程度上能批量处理名称不同但拥有相同含义图标。 
  
  
## 创建一套图标主题

  创建一套图标主题时，首先你需要对index.theme文件有更全面的了解,index.theme文件中会包含以下字段:   
  
  | 键值 | 含义 | 数据类型 | 是否必须 |
  | :---- | :------------ | :---: | :---: |
  | Name | 当前图标主题的短名称，用于选择主题时 | localestring | 是 |
  | Comment | 描述当前主题的较长字符串 | localestring | 是 |
  | Inherits | 当前主题继承自的主题的名称。如果在当前主题中找不到图标名称，则会在继承的主题中搜索该图标名称（并在所有继承主题中递归搜索）。如果没有指定主题，则需要实现将“hicolor”主题添加到继承树中 | strings | 否 |
  | Directories | 当前主题的子目录列表。对于每个子目录，在index.theme文件中都必须有一个部分来描述该目录 | strings | 是 |
  
  
  在Directories键中指定的每个目录都有一个与目录同名的相应部分。

  | 键值 | 含义 | 数据类型 | 是否必须 |
  | :---- | :------------- | :---: | :---: |
  | Size | 此目录中图标的尺寸大小 | integer | 是 |
  | Context | Context允许设计者在概念级别上对图标进行分组 | string | 否 |
  | Type | 此目录中图标的图标大小类型。有效类型为“Fixed”、“Scalable”和“Threshold”。类型决定部分中使用的其他键。如果未指定，则默认值为“Threshold” | string | 否 |
  | MaxSize | 指定此目录中的图标可以缩放到的最大大小。如果不存在，则默认为“Size”值 | integer | 否 |
  | MinSize | 指定此目录中的图标可以缩放到的最小大小。如果不存在，则默认为“Size”值 | integer | 否 | 
  | Threshold | 如果该目录中的图标大小与所需的大小相差最多这么多，则可以使用该目录下的图标。如果不存在，则默认为2  | integer | 否 |
  

  图标查找机制有两个全局设置，即基本目录列表和当前主题的内部名称。考虑到这些，我们需要指定如何从图标名称和标称大小查找图标文件。
查找首先在当前主题中进行，然后在当前主题的每个父主题中递归进行，最后在名为“hicolor”的默认主题中进行（实现可能会在“hiccolor”之前添加更多默认主题，但“hicolo”必须是最后一个）。只要有任何大小的图标与主题匹配，搜索就会停止。  

  主题内部的查找分三个阶段进行。首先，扫描所有目录以查找完全匹配的内容，例如，允许的图标文件大小与查找的内容相匹配的目录。然后扫描所有目录，查找与名称匹配的任何图标。如果失败了，我们最终会选择Scalable的图标。如果我们根本找不到任何图标，那么就由应用程序来选择一个好的后备方案，因为正确的选择取决于Context。

  了解完index.theme相关设置后，根据你的需求创建对应图标存放的目录以及index.theme文件，即完成了一套图标主题的创建。再将创建好的主题目录放入系统合适的位置，即可在你的环境中使用你创建的主题了。
