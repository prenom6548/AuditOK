# packaging sig组评审规则
## 一、评判标准
### 1. 评判依据
- pr数量

根据提交的pr数量来判断；

提交的pr数量越多，相应的得分也越多。

- pr的提交内容

pr的提交类型，是解决bug还是功能特性开发；

bug的严重程度越高得分也越高；功能特性开发，功能越完整、越重要得分越高。

- 代码质量

代码逻辑清晰、格式规整，有清晰的代码注释，易于理解；

代码质量越高，得分越高。

- 代码评审

如果是maintainer，需要评审pr的提交以及代码的审核等；

根据评审的pr数量来判断，数量越高得分越高。

- 参与技术决策

参与到社区软件包的技术决策中，提出有建设性的需求，能制定详细的规划流程等。

### 2. 评判规则

**- 日常贡献积分计算规则**

**贡献积分 = b * n * 3 + c * n * 2 + d * n**

b: pr的提交内容，分值[1,5]

c: 代码质量，分值[1,3]

d: maintainer评审的pr数量，如果不是maintainer该项分值为0，分值[0,5]；

n: 提交的pr数量

**- 首次贡献源代码**

**贡献积分 = 50 * n**

n: 源码包的上传数量

如果是maintainer首次将源码包贡献上传到openkylin，那么每个源码包奖励`50`分

**- 参与软件包的技术决策**

**贡献积分 = a * n * 3**

a: 技术决策，有效的需求、建议等，分支[1，5]

n: 提出的有效需求数量
