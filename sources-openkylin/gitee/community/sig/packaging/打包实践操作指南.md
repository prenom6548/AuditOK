# openKylin打包实践操作指南

本文档通过获取一个上游软件包的源代码，实际演示作为maintainer角色进行openkylin打包的操作流程。

通过该示例，可以方便快速入手，初步了解openkylin的一个常规打包流程。

## 一、从上游源码构建出debian规范的源码包

### 1. 获取上游源码

我们先要获取上游源代码。

下载 [debhello-0.0.1.tar.gz](http://archive.build.openkylin.top/resources/debhello-1.0.0.tar.gz)，并解压。

```sh
# tar -xzf debhello-0.0.1.tar.gz
# tree debhello-0.0.1
debhello-0.0.1
├── LICENSE
├── Makefile
└── src
    └── hello.c

1 directory, 3 files
# 注意：压缩包名的版本号与源代码文件版本号要保持一致。
```

作为演示的例子，这里的源代码很简单。

```sh
# ls debhello-0.0.1/
LICENSE  Makefile  src
```

`debhello-0.0.1/src/hello.c`文件的内容如下：
```sh
#include <stdio.h>

int main(void)
{
	printf("hello,openkylin!\n");
	return 0;
}

```

同时可以看到Makefile文件，我们知道，通常这一类源代码可以用这样的方式安装成为非系统文件：

```sh
# cd debhello-0.0.1/
# make
# make install
```

而我们openkylin打包的目的是需要对make install流程进行改变，从而使软件包的安装管理更简化。
话不多说，马上开始进入正式打包流程。

### 2. 使用 debmake 产生模板文件

进入源码目录，执行`debmake`

I: $ ln -sf debhello-0.0.tar.gz debhello_0.0.orig.tar.gz
I: pwd = "/home/deb_test/openkylin_show_3/examples/debhello-0.0.1"
I: parse binary package settings: 
I: binary package=debhello Type=bin / Arch=any M-A=foreign
I: analyze the source tree
I: build_type = make

I: check_all_licenses

I: format_all_licenses

I: creating => debian/changelog

debmake命令基于命令行选项产生所有这些模板文件。下面我们来检查一下debmake命令运行后的源码树：

```sh
# cd ..
# tree

│   │   ├── changelog

```

此时多出了一个debian的目录，该目录下包含rules，control，changelog等相关功能配置文件。

这里的 debian/rules 文件是应当由软件包维护者提供的构建脚本。

debian/control 文件提供了 Debian 软件包的主要元信息。

debian/copyright 提供了 Debian 软件包版权数据的总结。

具体的文件详细内容请参考社区《openkylin打包指南》。

### 3. 编辑debian目录模板文件

- 查看并修改debian/changelog文件，修改对应的版本号，版本信息描述等

```sh
debhello (0.0.1-1) UNRELEASED; urgency=low

  * Initial release. Closes: #nnnn
    <nnnn is the bug number of your ITP>（根据实际情况，添加注释说明）

 -- Luoyaoming <luoyaoming@kylinos.cn>  Mon, 18 Jul 2022 10:35:46 +0800
```

将版本号修改为0.0.1-ok1，UNRELEASED修改为当前发行版本yangtze。修改后的文件内容如下所示：

```sh
debhello (0.0.1-ok1) yangtze; urgency=low

  * Initial release. Closes: #nnnn
    <nnnn is the bug number of your ITP>（根据实际情况，添加注释说明）

 -- Luoyaoming <luoyaoming@kylinos.cn>  Mon, 18 Jul 2022 10:35:46 +0800
```

- 查看并修改debian/control文件，添加编译当前项目所需要的依赖软件包。

例如，此处需要使用debhelper来进行编译，因此需要将debhelper的编译依赖添加上去。

```sh
Source: debhello
Section: unknown（此处可修改为devel）
Priority: optional
Maintainer: Luoyaoming <luoyaoming@kylinos.cn>
Build-Depends: debhelper (>=11~), gcc
Standards-Version: 4.1.4
Homepage: https://openkylin.top

Package: debhello
Architecture: any
Multi-Arch: foreign
Depends: ${misc:Depends}, ${shlibs:Depends}
Description: auto-generated package by debmake
 This Debian binary package was auto-generated by the
 debmake(1) command provided by the debmake package.
```

本步骤需要根据上游软件的实际情况处理，根据不同的构建编译工具，做不同的修改。参考社区《openkylin打包指南》详细章节后，可以对复杂的软件包进行封装构建。

### 4. 打包当前上游软件包，生成规范化格式文件

执行dpkg-buildpackage打包上游源码。

```sh
# dpkg-buildpackage -S -nc --no-sign
dpkg-buildpackage: info: source package debhello
dpkg-buildpackage: info: source version 1.0.0-ok1
dpkg-buildpackage: info: source distribution yangtze
dpkg-buildpackage: info: source changed by Lu zhiping <luzhiping@kylinos.cn>
 dpkg-source --before-build .
dpkg-buildpackage: warning: building a source package without cleaning up as you asked; it might contain undesired files
 dpkg-source -b .
dpkg-source: info: using source format '3.0 (quilt)'
dpkg-source: info: building debhello using existing ./debhello_1.0.0.orig.tar.gz
dpkg-source: info: building debhello in debhello_1.0.0-ok1.debian.tar.xz
dpkg-source: info: building debhello in debhello_1.0.0-ok1.dsc
 dpkg-genbuildinfo --build=source
 dpkg-genchanges -sa --build=source >../debhello_1.0.0-ok1_source.changes
dpkg-genchanges: info: including full source code in upload
 dpkg-source --after-build .
dpkg-buildpackage: info: full upload (original source is included)
```

至此，完成了对上游源码的debian格式化打包流程。

通过以上步骤，我们得到了一个符合deb规范的软件包，该软件包可以通过dpkg方便来进行管理。

## 二、在openkylin社区创建软件包仓库

1. fork openkylin/community 仓库到个人仓库中

在浏览器网页端fork`openkylin/community`仓库到个人仓库。

2. 创建软件包维护信息

进入到一级目录packages里面，创建`debhello.yaml`文件，添加以下内容：

```yaml
name: debhello
path: debhello
maintainers:
- name: luzhiping
  openkylinid: lllcky
  displayname: 陆志平
  email: luzhiping@kylinos.cn
```
软件包yaml文件维护信息的字段，可以到
[Per-package-maintainer相关信息规范化存储](https://gitee.com/openkylin/community/tree/master/packages#per-package-maintainer%E7%9B%B8%E5%85%B3%E4%BF%A1%E6%81%AF%E8%A7%84%E8%8C%83%E5%8C%96%E5%AD%98%E5%82%A8)中进行查阅

3. 将改动推送到个人远端仓库中，并向openkylin/community仓库提交pr

```sh
git add sig/packaging
git commit -m "添加debhello软件包维护信息"
git push origin master
```

推送到个人仓库之后，在web页面端发起`Pull Requests`请求

对应的sig组维护者审核通过并接受pr之后，openkylin平台内部会根据软件包维护信息中描述的内容自动创建相应openkylin仓库。

例如，上面的`debhello`软件包的pr请求合并之后，会创建出名为`debhello`的openkylin仓库，可以在浏览器中访问该仓库，这里`debhello`软件包对应的仓库地址为：`https://gitee.com/openkylin/debhello`

## 三、将构建出的debian化源码包，反向构建到git仓库

下面我们需要将打包好的软件包反向构建出git仓库，然后推送到gitee托管平台。

### 1. 下载安装git-buildpackage软件包

```sh
sudo apt install git-buildpackage
```

### 2. 导入源码到指定分支git仓库

- 通过源码构建出git仓库

```sh
gbp import-dsc --pristine-tar --debian-branch=openkylin/yangtze --upstream-branch=upstream debhello_0.0.1-ok1.dsc debhello
```
其中：

--pristine-tar

记录原始orig tar 包的数据，避免重新用 gbp 打包后 tar 包内容发生变化。 pristine tar 分支（ Git 存储库中使用的默认分支名称是 pristine tar ）包含必要的附加信息，以从上游分支重新创建原始tarball 。 要使用此功能，您需要安装 pristine-tar 软件包。

--debian-branch=

指定打包分支名称，openkylin/yangtze 当前openkylin的版本系列。debian
branch Git 存储库中使用的默认分支名称是 master ）保存当前的开发工作。 这是通常用来发布版本的分支，并且新的上游版本会合并到该分支上。

--upstream branch=

指定上游分支名称，需为upstream。

- 新建打包分支

```sh
# 进入源码构建目录
cd debhello
# 创建quilt的分支，用于正式打包
git branch packaging/openkylin/yangtze
```
- 修改源码格式为native格式

```sh
# 在源码构建目录中执行
# 修改format格式
echo "3.0 (native)" > debian/source/format
#提交改动
git add debian
git commit -m "changed debian/source/format to native"
```

### 3. 推送到git仓库

```sh
git remote add origin git@gitee.com:openkylin/debhello.git
git push --tags
git push --all
```

此时可到gitee平台中找到对应的仓库，查看源代码是否推送成功。
