# 问题反馈

在使用 Kylin-IDE、Kylin-Code 或相关插件时，如果遇到功能异常、
安装失败、界面显示错误或使用文档问题，可以通过 Gitee Issue
向对应项目反馈。

为了帮助维护者快速理解和定位问题，请在提交前确认目标仓库，
并尽可能提供完整、可复现的信息。

## 1. 选择正确的反馈仓库

| 问题类型 | 建议反馈位置 |
|---|---|
| extensions-repo 中的帮助文档、插件汇总或配置文件问题 | [extensions-repo Issues](https://gitee.com/openkylin/extensions-repo/issues) |
| Kylin-Code IDE 基础平台问题 | [Kylin-Code Issues](https://gitee.com/openkylin/kylin-code/issues) |
| Kylin-IDE IDE 基础平台问题 | [Kylin-IDE Issues](https://gitee.com/chriswang521/kylin-ide/issues) |
| 某一个具体插件的问题 | 优先在该插件对应的代码仓库中提交 Issue |

如果无法判断问题属于哪个仓库，可以先在 extensions-repo 中
说明使用的软件、插件名称和问题现象，由社区成员协助确认。

## 2. 提交前检查

提交 Issue 前，建议完成以下检查：

1. 在目标仓库的 Issues 中搜索错误提示、功能名称和插件名称；
2. 确认是否已经存在相同或相近的问题；
3. 记录操作系统、软件和插件的版本；
4. 重新操作一次，确认问题是否能够稳定复现；
5. 尽量整理出最少且清晰的复现步骤；
6. 准备必要的截图或日志；
7. 删除截图和日志中的密码、令牌、私人路径和其他敏感信息。

如果已经存在相同 Issue，建议在原 Issue 中补充新的环境信息或
复现结果，不要重复创建内容相同的 Issue。

## 3. 建议提供的信息

一份完整的问题反馈通常应包括：

- 简洁明确的标题；
- 操作系统名称、版本和系统架构；
- Kylin-IDE、Kylin-Code 或插件的名称与版本；
- 问题出现的概率；
- 可以重复执行的复现步骤；
- 预期结果；
- 实际结果；
- 错误提示、截图或日志；
- 已经尝试过的解决方法。

标题应描述具体问题，避免只使用“不能用”“报错”“有问题”等
过于宽泛的表述。
