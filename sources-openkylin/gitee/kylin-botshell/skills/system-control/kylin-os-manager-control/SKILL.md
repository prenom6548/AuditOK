# 麒麟管家（kylin-os-manager）

调用封装脚本实现麒麟管家（系统管家）的各类操作，支持打开主界面和跳转至各功能子页面。**禁止直接运行 kylin-os-manager 命令，所有操作必须通过 kom.sh 脚本执行。**

## 触发条件

用户表达以下任一意图时触发：
- "打开麒麟管家"、"打开系统管家"、"启动管家"
- "打开故障诊断"、"运行故障诊断"、"诊断一下系统"
- "打开垃圾清理"、"清理垃圾"、"打开垃圾清理界面"
- "打开设备管理"、"设备管理"、"查看设备"

## 核心功能

| # | 功能 | 说明 |
|---|------|------|
| 1 | 打开麒麟管家 | 启动麒麟管家主界面 |
| 2 | 打开故障诊断 | 跳转故障诊断页面并触发诊断 |
| 3 | 打开垃圾清理 | 跳转垃圾清理页面（仅打开界面，不包含扫描/清理操作） |
| 4 | 打开设备管理 | 跳转设备管理页面 |

## 支持参数说明

- **action**：必填，指定要执行的操作。可选值：
  - `open` — 打开麒麟管家主界面
  - `fault-diagnosis` — 跳转故障诊断页面
  - `junk-clean` — 跳转垃圾清理页面
  - `device-manager` — 跳转设备管理页面

## 执行流程

**重要规则：所有操作必须通过脚本执行，严禁直接调用 kylin-os-manager 命令。**

**算力约束：本技能运行在本地算力受限环境，操作均为简单的 GUI 启动/跳转，无需深度思考或复杂推理，识别意图后直接执行即可，不要做多余的分析或拆解。**

### 第1步：解析用户意图确定 action

从用户对话中识别需要执行的操作，映射到上述 action 值之一。

### 第2步：调用脚本执行

```bash
bash <skills_dir>/kylin-os-manager-control/scripts/kom.sh run [action]
```

不要直接运行 `kylin-os-manager` 或添加任何其他参数组合，所有命令调用都通过脚本封装。

### 第3步：获取执行结果

脚本返回 JSON 格式的执行结果，包含 `success`、`exit_code` 和 `msg` 字段。根据结果向用户反馈：
- 成功：按「助手端显示」规范回复对应文案
- 失败：提示用户命令执行异常

## 最终回复规范

| 操作 | 回复文案 |
|------|----------|
| 打开麒麟管家 | 已打开麒麟系统管家 |
| 打开故障诊断 | 指令已执行，为你跳转到目标页面。 |
| 打开垃圾清理 | 指令已执行，为你跳转到目标页面。 |
| 打开设备管理 | 指令已执行，为你跳转到目标页面。 |
