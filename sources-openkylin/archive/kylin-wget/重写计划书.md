# wget Rust 重写计划书

最近更新：2026-03-31（**批次 AX**：`-A/-R（accept/reject）` 深水区对齐：对齐 GNU `acceptable()/in_acclist()`（通配 `fnmatch`、无通配后缀 `match_tail`、逗号多后缀、支持多次 `-A/-R` 追加、reject 覆盖 accept），并补齐目录 URL 与 `--default-page` 的交互与无扩展名边界；新增 **TC149–TC153**；回归全绿。其余同前）

本仓库目标：**按既定 Rust 重构 rule/skill 要求，用纯 Rust 重写 wget（优先 clap + Rust crate 替代 C 依赖）**。  
重构完成后，**对调用方可见的行为须与 GNU Wget 对齐**（CLI、退出码、常用协议与文件语义），使脚本与打包可迁移。  
详尽定义与验收方式见 **`docs/功能对等目标.md`**；GNU 全量选项清单见 **`docs/gnu_wget_options_inventory.md`**（由脚本从 `main.c` 生成）。

进展将以「阶段状态 + 可验收产物 + commit」方式持续记录在本文件中。

## 总体原则（来自 rule/skill，执行时强制遵守）

- **Rust 拥有所有数据与逻辑**：业务状态、下载流程、重试/限速/续传等都在 Rust 内完成。
- **CLI 工具优先纯 Rust**：wget 属 CLI，无需 C++/Qt 桥接；直接 Rust 实现。
- **GNU 功能对等（长期）** 与 **单次提交最小改动（短期）** 同时成立：迭代内只做必要补丁，矩阵与清单跟踪直至计划内条目全部 **已完成**。
- **避免「空逻辑/恒等」**：实现必须有实际逻辑与可验证行为。**禁止对已实现/已声明的选项静默忽略**（未实现应报错或文档明示降级）。
- **最小化修改/不过度设计**：每阶段只引入支撑该阶段目标的最小代码与依赖。
- **结构随能力增长而拆**：建客户端、组请求、写响应三类逻辑分层，避免单文件堆叠。

## 附录：阶段 3 预期的 10 条验收用例（边界定义）

1. `wget https://example.com/a.txt` → 生成 `a.txt`，退出码 0  
2. `wget -O out.txt https://example.com/a.txt` → `out.txt`，退出码 0  
3.             `wget -q -O out.txt …` → 无多余输出，退出码 0  
4. 404 → 失败，退出码非 0  
5. HTTPS 成功场景 → 退出码 0  
6. 302 → 最终内容与预期一致  
7. 超时场景 → 失败  
8. flaky + tries → 最终成功或一致失败语义  
9. `-c` 续传 → hash 正确  
10. `--limit-rate` → 速率受限且成功
