# wget 外部接口说明（对齐目标）

更新时间：2026-03-30  
基准实现来源：`/home/zoey/code/gerrit/wget`

本文件描述 **wget 对外可见的接口**（主要是命令行参数、输入输出与退出码语义），用于指导 `wget-rust` 的兼容实现。

**全功能对等**的总体约定与验收：见 [`功能对等目标.md`](功能对等目标.md)。**全量长选项枚举**（源码生成）：见 [`gnu_wget_options_inventory.md`](gnu_wget_options_inventory.md)。

---

## 1. 入口与总体调用形态

### 1.1 Usage

从 `src/main.c` 可见 usage 形态为：

- `Usage: wget [OPTION]... [URL]...`

### 1.2 输入来源

- **命令行 URL 列表**：`wget URL1 URL2 ...`
- **输入文件**：`-i, --input-file=FILE`（纯文本一行一个 URL，trim，空行跳过；**FILE 为 `-` 时读 stdin**；**处理顺序在命令行 URL 之后**，对齐 GNU `main.c`）  
- **基 URL**：`-B, --base=URL`（与 `-i` 中相对 URL 合并）  
- **`-F, --force-html` + `-i`**：按 HTML 解析抽取链接（与 GNU `get_urls_html` **行为子集**一致：见 `rust/src/html_urls.rs` 与 `docs/兼容矩阵.md`）；无 `-B` 且无 `<base href>` 时 **相对 URL 会警告并跳过**（对齐 GNU `Cannot resolve incomplete link`）  
- （可选）Metalink：`--input-metalink=FILE`（受编译特性影响）

## 2. 退出码（稳定接口）

> 说明：`wget-rust` 对 **自定义校验**（`wget: …` 的互斥/缺 URL 等）使用 **退出码 1**（`WGET_EXIT_GENERIC_ERROR`），与 GNU wget `main.c` 中多数启动期校验一致，而非 2。

定义于 `src/exits.h`：

| 退出码 | 含义 |
|---:|---|
| 0 | 成功 |
| 1 | 通用错误（很多未知/兜底错误会映射到 1） |
| 2 | 参数/配置解析错误 |
| 3 | IO 失败（打开/写入/关闭/删除文件等） |
| 4 | 网络失败（连接/读写/重试次数耗尽等；不含 TLS 证书类） |
| 5 | SSL 认证失败（证书校验失败等；`reqwest` 错误链判定为 TLS/证书时映射） |
| 6 | 服务端认证失败（HTTP Basic 已尝试仍 **401** 等） |
| 7 | 协议错误（HTTP/FTP 协议层错误；**预留**，当前枚举已定义、逐步挂场景） |
| 8 | 服务端错误（例如 HTTP 非成功状态等被归类） |

> 兼容目标：`wget-rust` 需要尽量把错误归类到同样的退出码，至少保证 **脚本依赖的 0/非0 语义**不变，并逐步对齐 2/3/4/5/6/8 等常见类别。  
> **`--no-clobber` 跳过已存在目标**：GNU 为 **退出码 1**（非 0），`wget-rust` 对齐。

### 2.1 `-V, --version`

- GNU：首行形如 `GNU Wget 1.20.3 built on linux-gnu.`（随构建与语言环境变化）。
- `wget-rust`：**首行** `GNU Wget compatible 1.20.3 (rust <crate 版本>) built on linux-gnu.`，后续行为目标/版权说明与 GNU 多行输出**不完全相同**；**TC71** 覆盖「stdout 含 `GNU Wget`」与 rust 标识。

## 3. 关键 CLI 参数（对外接口清单：第一版）

> 说明：原 wget 支持参数非常多。本项目将按“阶段”逐步兼容。  
> 本清单以 `src/main.c` 的 help 文本与 `option_data[]`（命令行解析表）为准。

### 3.1 启动类

- `-V, --version`
- `-h, --help`
- `-b, --background`
- `-e, --execute=COMMAND`（执行 `.wgetrc` 风格命令）
- `--config=FILE` / `--no-config`（配置文件加载）

#### 3.1.1 `.wgetrc / --no-config / --config / WGETRC`（加载顺序与覆盖规则）

对齐 GNU `src/main.c`/`src/init.c` 的可见行为（本项目当前实现为**已支持选项**提供配置默认值注入）：

- **默认加载**：未指定 `--config` 且未指定 `--no-config` 时，读取 `$HOME/.wgetrc`（若存在）。
- **`WGETRC` 环境变量**：若设置且非空，则使用它指向的文件替代 `$HOME/.wgetrc`；若文件不可访问则退出（GNU 为 generic error）。
- **`--config=FILE`**：若指定，则仅读取该文件作为用户配置；解析失败按“配置解析错误”退出。
- **`--no-config`**：禁用所有配置文件读取。
- **覆盖规则**：配置文件提供“默认值”，命令行参数覆盖配置值（含重复指定 last-wins）。

#### 3.1.2 `-e, --execute=COMMAND`（执行 `.wgetrc` 风格命令）

对齐 GNU `src/init.c:run_command()`：

- **语法**：`COMMAND` 形如 `name=value`（等价 `.wgetrc` 单行命令）。
- **执行时机**：按命令行出现顺序生效（可与其它参数交错，最终以 last-wins 决定生效值）。
- **错误处理**：命令解析失败或未知命令会退出（GNU 为 parse error）。

#### 3.1.3 `-b, --background`（后台模式）

对齐 GNU `utils.c:fork_to_background()` 的可见行为（本项目用“spawn 自身进程”实现同等效果）：

- **父进程行为**：打印 `Continuing in background, pid <pid>.` 并以退出码 0 退出。
- **默认日志文件**：若未指定 `-o/-a` 且（非 quiet 或启用 `-S`），会创建 `wget-log`（必要时 `wget-log.1`…）并提示 `Output will be written to <file>.`。
- **子进程行为**：继续下载；标准输入/输出/错误被重定向到空设备，日志依然通过 `-o/-a` 落盘。

### 3.2 日志与输入

- `-o, --output-file=FILE`
- `-a, --append-output=FILE`
- 日志落盘语义：该 FILE 用于写入非下载“消息行”（成功写 `URL:...`；HTTP 错误写 `ERROR code: reason`）。`-q` 时日志落盘为空。
- `-q, --quiet`（与 `-v/--verbose` 不能同时使用，退出码 1）
- `-v, --verbose`（与 `--no-verbose` 互斥；未指定 `--no-verbose` 且非 `-q` 时，GNU 默认偏「详细」；`wget-rust` 用 `effective_verbose()` 对齐）
- `-n FLAGS`（GNU `OPT__NO`）：`FLAGS` 支持 `v/H/d/c/p` 五个字母（可组合），等价于 `--no-verbose` / `--no-host-directories` / `--no-directories` / `--no-clobber` / `--no-parent`。并对齐 GNU：`-v/--verbose` 与 `-q/--quiet` 若最终同时生效则报错退出；`-v` 与 `-n v`（`-nv`）允许同时出现，按命令行顺序后者覆盖前者（last-wins）。
- `--show-progress`（无 Content-Length 时无百分比条；`-q` 时仍不显示）
- `-E, --adjust-extension`：按响应 `Content-Type` 自动为 HTML/CSS 文件补全扩展名（`.html` / `.css`），对齐 GNU `ensure_extension()` 行为
- `--backups=N`：写入文件前做轮转备份，最多保留 N 份：`X.1`、`X.2`…（对齐 GNU `rotate_backups()`）
- `-i, --input-file=FILE`
- `-F, --force-html`
- `-B, --base=URL`
- `--config=FILE`
- `--no-config`

### 3.2.1 HTTP 资源认证（服务端，非代理）

- `--http-user` / `--http-password`：HTTP **Basic**（默认待 **401** + `WWW-Authenticate: Basic` 后再带凭据重试；与 GNU 默认行为一致方向）
- `--user` / `--password`：在 URL 未嵌入凭据且未指定 `--http-user` 时作 HTTP 后备（对齐 GNU 优先级链的一截）
- `--auth-no-challenge`：未收到 401 即发送 Basic（GNU 同名）
- `--https-only`：对齐 GNU `recur.c`：仅在**递归**模式下生效——入队前拒绝一切非 HTTPS 链接（包括绝对 `http://` 与从 HTTPS 页面解析出的非 HTTPS）；并且当发生重定向时，若重定向目标变为非 HTTPS，则停止跟随该重定向链（避免“递归时偷偷落到 HTTP”）；非递归下载不因 `http://` 而拒绝（与 GNU 一致）；**TC163**
- `--robots[=on|off]`：递归时是否遵守 `robots.txt` 与 HTML 的 `<meta name="robots" ...>`（默认 `on`）。若 meta 含 `nofollow` 或 `none`，则该页面**不跟随任何链接**（对齐 GNU `meta_disallow_follow` 行为）

### 3.3 下载核心（优先级最高）

- `-O, --output-document=FILE`（支持 `-` 输出到 stdout）
- `-N, --timestamping`（已完成）：若本地目标文件已存在，则发送 `If-Modified-Since` 条件请求；收到 **304 Not Modified** 则跳过写入并成功退出；若服务端忽略 IMS 仍返回 **200**，则在 `Last-Modified <= 本地 mtime` 且长度一致时跳过下载；成功下载后默认按 `Last-Modified` 回写本地 mtime（可用 `--no-use-server-timestamps` 关闭）；`-O -` 与 `-N` 互斥
- `--use-server-timestamps` / `--no-use-server-timestamps`：控制“成功下载后是否按服务端 `Last-Modified` 回写本地 mtime”（GNU 默认开启）
- `-c, --continue`
- `--start-pos=OFFSET`
- `-t, --tries=NUMBER`
- `-T, --timeout=SECONDS`
- `--connect-timeout=SECS`
- `--read-timeout=SECS`
- `--limit-rate=RATE`
- `--max-redirect=NUMBER`
- `--retry-connrefused`（连接被拒绝时，是否按 `--tries` 重试；默认不重试）
- `--retry-on-http-error=ERRORS`
- `--retry-on-host-error`（DNS/主机解析失败时是否按 `--tries` 重试；默认不重试）
- `--spider`
- `-P, --directory-prefix=PREFIX`：若未指定 `-O`，则把落盘文件整体放到 `PREFIX/` 下；递归目录树落盘时为 `PREFIX/host/...`（对齐 GNU `opt.dir_prefix`）
- `-x, --force-directories`：强制启用“目录树落盘”（GNU `dirstruct`），即使**非递归单 URL**也会把文件保存到 `host/path/...` 结构下（仍受 `-P/--directory-prefix` 影响）。与 `-nd/--no-directories`（或 `-n d` / `-nd`）冲突时，按 argv 顺序**后者覆盖前者（last-wins）**。
- `-nH, --no-host-directories` / `--host-directories`：递归目录树落盘是否创建 `host/` 这一层目录；默认创建；支持 argv 后者覆盖前者；并兼容 `-nH`（通过 `-n FLAGS` 兼容路径）
- `--protocol-directories`：递归目录树落盘时在 `host/` 前插入协议目录（如 `http/`）；与 `--no-host-directories` 组合时仍会生成协议目录（对齐 GNU `opt.protocol_directories`）
- `--cut-dirs=NUMBER`：递归目录树落盘时，忽略远端路径的前 NUMBER 个目录段（只影响目录结构；文件名段保留）；在 `--no-directories` 下无效（对齐 GNU `opt.cut_dirs`）
- `--default-page=NAME`：改变“目录 URL”的默认落盘文件名（GNU 默认 `index.html`）。当 URL 的 path 为空或以 `/` 结尾，且未指定 `-O` 时，默认文件名使用 NAME；允许重复指定，按 argv 顺序**后者覆盖前者（last-wins）**。与 `-x/--force-directories` 联动时会落在 `host/dir/NAME` 下。
- `--trust-server-names`：当未指定 `-O` 且未启用 `--content-disposition` 时，若发生重定向则使用最终重定向 URL 的最后一段作为本地文件名；递归时同样以最终 URL 计算落盘路径（对齐 GNU `url_file_name(opt.trustservernames ? u : original_url)`）
- `--delete-after`：成功下载后删除本地文件；在递归/`-p` 抽链场景中，用于解析的 HTML/CSS 文件也会在抽链后删除；与 `-k/--convert-links`、`--convert-file-only` 不共存（GNU 的转换链路在 `--delete-after` 时不会执行）
- `--restrict-file-names=OS`：限制 URL 推导的本地文件名字符集与形态（对齐 GNU `url.c:append_uri_pathel`）。值为逗号分隔子选项：
  - OS：`unix` / `vms` / `windows`
  - case：`lowercase` / `uppercase`
  - flags：`nocontrol`（允许控制字符） / `ascii`（限制非 ASCII）
  
  行为要点：
  - URL path segment 会先做 `%XX` 解码，再把不安全字符编码为 `%HH`（大写十六进制），并对 `..` 组件做去危险化。
  - Windows 规则下 host:port 的分隔符使用 `+`（避免 `:`）。
  - 当 URL 含 query（`?a=b`）时，GNU 会把 query 也拼进文件名：unix 使用 `?`，VMS/Windows 使用 `@` 作为分隔符；并同样受 `--restrict-file-names` 的 `%HH` 转义与大小写规则影响（本仓库已对齐）。
  
  测试覆盖：**TC178–TC179、TC187–TC189**。
- `--iri` / `--no-iri`：IRI 支持开关（对齐 GNU `ENABLE_IRI` 编译分支的可见行为）。本仓库对齐点：
  - 默认启用（等价 `--iri`）
  - 支持显式 `--no-iri` 关闭，以及显式 `--iri` 开启
  - 若两者同时出现，按 argv 顺序 **last-wins**（后者覆盖前者）
  - 在我们覆盖的场景中（UTF-8 path），`--no-iri` 下仍应可下载并落盘 UTF-8 文件名
  
  另外，对齐 GNU `url.c`：当 host 含 `%HH` 转义时，会先对 host 做 `%HH` 解码（然后再按需走 IDNA 编码）；本仓库已补齐该路径。
  
  测试覆盖：**TC180–TC182、TC190**。
- `--netrc` / `--no-netrc`：是否从 `$HOME/.netrc` 获取 HTTP/FTP 凭据（对齐 GNU `netrc.c` + `http.c/ftp.c` 的使用方式）。本仓库对齐点：
  - 默认启用（等价 `--netrc`）
  - 支持 `--no-netrc` 禁用（并按 argv 顺序 last-wins）
  - 查找触发条件：当 user/pass 至少一边缺失时才尝试从 `.netrc` 填充
  - host 匹配大小写不敏感
  - HTTP：不使用 `default` 记录（slack_default=0）
  - FTP：允许使用 `default` 记录（slack_default=1）
  
  测试覆盖：**TC183–TC186**。
- `-S, --server-response`（将 **HTTP 响应状态行 + 头** 打到 stderr；行首缩进贴近 GNU；消费 body **之前**打印）

### 3.4 HTTP 常用

- `--header=STRING`
- `--user-agent=AGENT`
- `--referer=URL`
- `--save-headers`
- `--no-cookies` / `--load-cookies=FILE` / `--save-cookies=FILE` / `--keep-session-cookies`（Netscape cookies.txt 子集；`--save-cookies` 默认不保存 session；**TC79–TC81**）
- `--hsts` / `--no-hsts` / `--hsts-file=FILE`（HSTS DB：默认 `~/.wget-hsts`；HTTP 命中条目则改写为 HTTPS；**TC82**）
- `--method=HTTPMethod` / `--body-data=STRING` / `--body-file=FILE`
- `--post-data=STRING` / `--post-file=FILE`（内部会转换为 `--method POST + --body-*`）
- `--content-disposition`（深水区已对齐）：当 **未指定 `-O` 且非 `-c`** 时，按 `Content-Disposition` 选择本地文件名：
  - 支持 `filename*`（RFC5987/RFC6266：`UTF-8''...`，含 percent-decoding 与 charset 解码）
  - 支持 `filename*0/filename*1...` continuation（RFC2231：片段拼接）
  - 优先级：`filename*` 覆盖 `filename`
  - 与 `--trust-server-names`：若命中 Content-Disposition，则以响应头为准（即使发生重定向）
  - 递归模式同样生效（对资源文件的落盘名也会被 header 改写）
  
  测试覆盖：**TC42、TC42b–TC42g**。
- `--no-clobber`（目标已存在则跳过：**GNU 对齐——跳过仍退出码 1**；**`-nc`**、**`-n c`**）
- `--clobber`（允许覆盖；与 `--no-clobber` **以命令行后出现者为准**；可选 `--clobber=off` 等 GNU 子集）
- `--check-certificate`（可选 **`=on|off|quiet`** 子集；默认校验；与 `--no-check-certificate` **以命令行后出现者为准**）
- `--no-check-certificate`（HTTPS：接受无效证书；**仅建议测试/内网**）
- `--ca-certificate=FILE`（PEM 根证书 bundle，追加到 `reqwest` 信任库，与 Mozilla 默认根并存）
- `--ca-directory=DIR`（目录下每个**普通文件**尝试按 PEM 解析；GNU/OpenSSL 的「哈希目录」在测试里通过 `openssl rehash` 生成；**TC74**）
- `-4` / `--inet4-only`（仅连接 IPv4：DNS 结果过滤 + 字面量 IPv6 主机拒绝，**退出码 4**）
- `-6` / `--inet6-only`（仅 IPv6：对偶；**不可与 `-4` 同时指定**；校验失败 **退出码 1**）
- `--content-on-error`（HTTP 错误时仍把响应 body 写入文件；退出码仍按错误语义返回）
- `--ftp-user=USER` / `--ftp-password=PASS`：FTP 登录凭据（对齐 GNU 语义方向）；未指定时使用匿名登录（password 使用稳定默认值）；本批次实现 `PASV` + `RETR` 的最小闭环；**TC170、TC171**

### 3.5 代理（环境变量 + CLI）

GNU wget 主要通过 **环境变量** + `--no-proxy` 控制代理（见 `src/retr.c:getproxy`、`src/init.c` 对 `no_proxy` 的读取）。

- **环境变量**
  - HTTP URL：`http_proxy`（实现中同时接受 `HTTP_PROXY`）
  - HTTPS URL：`https_proxy`（同时接受 `HTTPS_PROXY`）
  - 绕过列表：`no_proxy`（同时接受 `NO_PROXY`；与原 wget 单读 `no_proxy` 相比，多一层常见生态兼容）
- **CLI**
  - `--no-proxy`：忽略环境变量代理；但不覆盖显式 `--proxy=...`
  - `--proxy=URL`：显式设置代理地址（覆写环境变量代理）
  - `--proxy-user=USER` / `--proxy-password=PASS`（deprecated: `--proxy-passwd`）：对代理的 HTTP Basic 认证（`Proxy-Authorization`）

> `wget-rust` 构建 `reqwest::Client` 时会先关闭其默认“系统代理”，再按上述规则显式挂载 `Proxy::http` / `Proxy::https`，以避免与 GNU wget 在 `ALL_PROXY` 等变量上行为不一致。

### 3.6 递归/站点镜像（已实现）

- `-r, --recursive`
- `-l, --level=NUMBER`
- `-m, --mirror`（完整语义：等价启用 `-r -N -l 0`，并隐含 `--dont-remove-listing`；后者主要影响 FTP，HTTP 场景无可见差异）
- `-p, --page-requisites`（已完成）：即使不带 `-r` 也会进入“树检索”链路，但只下载页面渲染所需的 **inline** 资源（例如图片/脚本/CSS/frames），不跟随普通页面跳转链接（如 `<a href>`）；同时对已下载 CSS 解析 `url(...)` 与 `@import` 继续下载资源（不再扩展跟随）
- `-k, --convert-links`（完整语义：用于递归下载后的离线浏览，把已下载页面中指向“已下载目标”的链接改为本地相对路径，未下载目标改为绝对 URL；同时适配目录树落盘与 `--no-directories` 扁平落盘）
- `-K, --backup-converted`：与 `-k` 联动；在写回转换后的文件前，先把原文件备份为 `X.orig`（同一文件仅备份一次）
- `--convert-file-only`：与 `-k` 的“改成相对本地路径”不同，它只改写 URL 的**文件名部分（basename）**为本地文件名（保留原 URL 的 dirname/host 等结构），用于“本地文件名可能变化（例如 Content-Disposition）但仍希望链接保持 URL 形态”的场景
- `-np, --no-parent`（本实现：支持 `--no-parent`；并兼容 `-np` 作为 `-n p` 的简写形式）
- `-nd, --no-directories`（本实现：支持 `--no-directories`；并兼容 `-nd` 作为 `-n d` 的简写形式）
- `-A, --accept=LIST` / `-R, --reject=LIST`：按“文件名”做 accept/reject 过滤；支持通配符；无通配符时做“后缀匹配”（对齐 GNU `acceptable()`/`match_tail()`）；支持逗号分隔与**多次指定追加**。当 accept 列表存在时，reject 命中会覆盖（拒绝）。对于**目录 URL**（path 为空或以 `/` 结尾），会用 `--default-page` 的有效文件名参与过滤。
- `--accept-regex` / `--reject-regex`：对 URL 全串做 regex 允许/拒绝（对齐 GNU `accept_url()`）
- `--accept-regex=REGEX` / `--reject-regex=REGEX`（深水区）：匹配对象为 **URL 全串**（包含 query）；若指定 `--accept-regex` 则必须命中才允许；若同时指定 `--reject-regex`，则 reject 命中会覆盖拒绝。递归场景下它在“入队前过滤”阶段生效（与 `-H/-L/-D/-I/-X/-A/-R` 同属跟随策略）。
- `-D, --domains=LIST` / `--exclude-domains=LIST`：按 host 后缀匹配允许/拒绝（对齐 GNU `accept_domain()`/`sufmatch()`）。匹配**大小写不敏感**；支持以 `.` 开头的模式（如 `.example.com`）；若同时指定 domains 与 exclude-domains，则 **exclude-domains 优先拒绝**。
- `-H, --span-hosts`：允许递归跨 host 跟随（默认不跨）。对齐 GNU：默认仅当 schemes 相似（HTTP/HTTPS）时要求“子链接 host 与父页面 host 相同”；启用后解除该限制，但仍受 `-D/--exclude-domains` 与 `-L/--relative` 等过滤影响。
- `-L, --relative`：只跟随“相对链接”（含 `/path`、`sub/a.html` 等；不含 `http://...`、`//...`）
- `-I, --include-directories=LIST`：只允许指定目录前缀/模式。对齐 GNU `accdir()/dir_matches_p()`：忽略 leading `/`；无通配时按“目录前缀+边界”（`p == dir` 或 `dir` 以 `p/` 开头）；有通配时按 `fnmatch(FNM_PATHNAME)`（`*` 不跨 `/`）；目录匹配对 URL path 做 `%XX` 解码。
- `-X, --exclude-directories=LIST`：排除指定目录前缀/模式。规则同上，且 **exclude 优先于 include**。

### 3.7 FTP（第一批 + 目录列表最小闭环）

- `--ftp-user=USER` / `--ftp-password=PASS`：FTP 登录凭据；未指定时匿名登录（password 使用稳定默认值）。
- 目录 URL（`ftp://.../dir/`）：会生成 `.listing`；默认删除，`--dont-remove-listing` 或 `-m/--mirror` 时保留；递归模式会解析 `.listing` 并下载目录内条目（最小闭环）。**TC170–TC174**

#### 3.7.1 FTP listing 过滤对齐（第三批）

对齐 GNU `ftp_retrieve_glob()` 的过滤顺序（只针对从 LIST 得到的条目；目录本身的 `.listing` 获取不受这些过滤影响）：

- **`-A/-R`（acceptable）**：仅对 **非目录** 条目按“文件名”过滤（目录条目不走 `acceptable()`，仍可能用于进入递归）。
- **安全/非法条目过滤**：
  - **安全文件名**：拒绝 **leading `/`** 或包含 **`../`** 的条目（对应 GNU `has_insecure_name_p()`）。
  - **重复条目**：listing 中同名条目视为非法，按 GNU 逻辑“拒绝前面的、保留最后一个”（对应 `is_invalid_entry()`）。
- **`--accept-regex/--reject-regex`（accept_url）**：对 **完整 URL 字符串** 做 regex 允许/拒绝（目录条目会参与匹配）。

测试覆盖：**TC175–TC177**。

本实现当前覆盖的递归语义（已扩展到 GNU 常用跟随策略）：

- **队列**：BFS（按深度扩展），去重（同一 URL 只下载一次）
- **深度**：默认 `-l 5`；`-l 0` 表示无限
- **抽链**：仅对 **成功** 且 `Content-Type` 为 `text/html` / `application/xhtml+xml` 的响应抽链；抽链规则复用 `rust/src/html_urls.rs`（与 `-F` 抽链同一子集）
- **同站点限制**：默认不跨 host（与 GNU `--span-hosts` 语义一致）；启用 `-H` 后允许跨 host（仍受 domains/regex/dir/accept 过滤）
- **`--no-parent`**：开启后，只允许跟随起始 URL 所在目录（例如起始为 `/recur/index.html`，则只允许 `/recur/...`），不越出到 `/other/...`
- **同站点/端口（深水区）**：对齐 GNU `recur.c`：默认不跨 host（当 schemes 相似时，以父页面 host 为准）；`--no-parent` 仅在 host 相同且 schemes 相似时生效，并且只有在“scheme 发生变化”或“port 相同”时才做目录前缀约束；因此同 host 但**端口不同（且 scheme 相同）**时会忽略 `--no-parent`。
- **descend_redirect（深水区）**：对齐 GNU `recur.c:descend_redirect()`：当下载发生重定向时，会对“最终 URL”按 `download_child` 做一次“是否继续递归”的判定；其中 **LIST（`-I/-X`）与 REGEX（`--accept-regex/--reject-regex`）对重定向目标会被忽略**（仍继续抽链/入队），但 **DOMAIN/SPANNEDHOST/ROBOTS/NO-PARENT/HTTPS-ONLY** 等仍会阻止继续递归；并且只有在“通过或仅因 LIST/REGEX 被拒绝”时才把最终 URL 加入去重集合。抽链后的子链接判断以**最终 URL**作为“父页面”（同 host 判断基准随重定向更新）。**TC161–TC167**
- **目录树**：默认递归会写入 `host/...` 的路径树；`--no-directories` 则落盘到当前目录（只用 URL 最后段文件名）
- **robots.txt（深水区）**：对齐 GNU `src/res.c`：仅匹配 `User-agent: wget` 或 `*`；若出现 `wget` exact 记录则丢弃 `*` 记录；匹配为“前缀匹配”（对路径做 `%XX` 解码但不解 `/`）；命中后按规则出现顺序 **first-match-wins**；缓存按 host:port 隔离；可用 `--robots=off` 关闭。
