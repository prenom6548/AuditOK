# 测试方案：原 wget vs wget-rust（自动化对照）

更新时间：2026-03-31

目标：用自动化脚本保证 **重写前后外部接口行为一致**（至少覆盖我们承诺的兼容矩阵条目）。

**阶段 7**：以 **`重写计划书.md` →「阶段 7 执行计划」** 为纲，持续把矩阵条目 **挂到 TC + server 路由**；本文件第三节表格随 TC 追加同步增长。

---

## 1. 总体思路（说人话）

我们做两层测试：

- **黑盒对照**：对同一组 URL/参数，分别跑“原 wget”和“wget-rust”，比较：
  - 退出码
  - 输出文件内容（字节级）
  - 关键 stdout/stderr 片段（可选）
- **可控服务器**：用本地小型 HTTP 服务器制造稳定场景（200/404/302/Range/慢响应等），避免依赖公网波动。

这样即使 `wget-rust` 内部实现不同，只要外部行为一致，其他组件就不会被影响。

---

## 2. 原 wget 的来源（可配置）

优先用环境变量指定：

- `WGET_ORIG=/path/to/original/wget`

如果未指定：

- 默认使用系统 `wget`（如果存在），用于先跑通对照框架

## 4. 自动化脚本（本仓库内）

- `tests/server.py`：本地可控 HTTP 服务器（生成 200/404/302/Range/slow 等场景）
- `tests/proxy.py`：最小 HTTP 正向代理 / “evil”代理（TC09–TC11）
- `tests/compare.py`：对照执行器（跑 orig 与 rust，比较退出码/文件内容；支持 `extra_env` 与 `--proxy-url`；**种子文本**中可写 `{BASE}` 占位符，写入前替换为真实 base URL；可选 **`expect_stderr_contains`** 在成功时双方 stderr 均须含子串）；占位符 **`{HTTPS}` / `{CAPATH}` / `{CADIR}`** 由 `run.sh` 传入 `--https-base-url` / `--ca-pem` / `--ca-dir`
- `tests/run.sh`：一键入口（启动 **HTTP + HTTPS** 两路 `server.py` 与 **三个** 代理 → 跑用例）；**默认同一套 TC 连续跑 3 遍**（`REGRESSION_PASSES`，可调为 `1` 加速）；对 **`tests/fixtures/tls/ca_dir`** 执行 **`openssl rehash`** 以配合 GNU **`--ca-directory`**
