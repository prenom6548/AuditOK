# 01a — Points d'entrée par composant (Phase 0.2, détail)

> Recensement **en lecture seule** des fichiers déclaratifs (unités systemd, D-Bus, polkit, scripts mainteneur, hooks APT,
> modules noyau, autostart, CMake/qmake…), produit par 14 agents puis contrôlé par un agent critique.
> Aucune logique applicative n'a été jugée. Chaque point d'entrée cite un fichier relatif à l'arbre `archive:` (source
> du paquet de l'archive par défaut) ou `gitee:` (clone superficiel). Registres : CONSTATÉ / PROBABLE / NON COUVERT.

## Contrôle critique et corrections appliquées

> Un agent critique indépendant a relu les 14 lots : **aucun composant omis** (329/329). Il a relevé 35 écarts
> et 21 points d'entrée manquants, tous intégrés ci-dessous (mention « [ajout critique] » / « [correction critique] »).

**Synthèse de la critique** : (a) Completude : les 14 fiches comptent 329 paquets et aucun n'a ete omis ; les noms correspondent exactement au recensement. (b) Budgets : la base du pourcentage n'est pas la meme partout. B12 calcule sur le delta, B13 et B02 sur l'arbre complet (vendoring compris), B11 est ambigu. On trouve donc des L3 a 2-3 % (cryptsetup, bluez, cups, kylin-code), des L2 a 3-15 % et des L1 a 100 %. Plusieurs demons root avec acces reseau, installes par defaut, sont classes L1 contrairement a la grille : avahi, strongswan, wpa, ainsi que bftpd (non installe, net=1). shadow (setuid root) est en L1. grub2-signed est en X/100 %. Trois cas identiques (squelette dans l'archive, code sur Gitee dans une autre version) recoivent X, L2 ou L3 selon le lot (B04, B06, B03). Les squelettes dh_make sont classes tantot absent-ou-vide, tantot reconditionnement-binaire. (c) Echantillon relu : 26 paquets a haut risque. On y trouve 21 points d'entree absents du recensement ou de la fiche. Les plus importants : la regle udev MODE=0666 sur le sous-systeme graphics de kylin-wayland-compositor (installee, et ce paquet est installe par defaut) ; la politique D-Bus de ukui-service-manager, qui autorise 'own' en contexte default sur org.ukui.serviceManager et sur le prefixe org.ukui.Service (service root qui charge les .so de ukui-control-center et ukui-search) ; les services D-Bus systeme root de libkysdk-base ; le compte sudo NOPASSWD du mode audit de l'installateur (cmdline auditmode/ple-mode) ; les fichiers apt.conf.d de kylin-system-updater (DPkg::Options --force-confnew global) ; les fichiers PAM non detectes par l'extracteur (ukui-control-center, ukui-screensaver, shadow, cups) ; le fichier debian/dkms effectif de KMRE. Plusieurs fichiers de la fiche ne sont pas installes (kylin-daq.timer, kylinbot.service, cron libkysdk-base, units ukui-power-manager) : le recensement doit le dire plutot que les taire. Liens inter-lots manquants : les plugins moteurs B02 sont charges par kylin-ai-runtime (B01) ; com.kylin.assistant.systemdaemon (root) est livre a la fois par kylin-os-manager (B07) et youker-assistant (B10) ; register-ukui-system-service (B07) est un script bash, pas un binaire hors lot. Cote couverture : policykit-1=124-ok6.1 est installe par l'ISO sans source correspondante, et B11 ne signale pas les orig EMPREINTE-DIFFERENTE (glibc, grub2, linux, policykit-1). (d) Registres : plusieurs PROBABLE reposent sur une connaissance generale et doivent passer en NON COUVERT (kylin-mfa, kydoctor, token-center, kylin-background-upgrade, sane backend, DaemonSet k8s). Trois constats depassent le perimetre 0.2 : semantique GDBusAuthObserver (B01), recherche de secrets (B02), logique de serviceregister.cpp (B07). Les constats negatifs sur les listeners (B04, B05, B09) doivent mentionner les limites de l'extracteur. Aucun fichier n'a ete modifie. Fiches lues dans $AUDIT_WORK/digest/ ; sources lues sous $AUDIT_SRC/archive et $AUDIT_SRC/gitee.

**Règles adoptées après critique** :

- Base de calcul unique des pourcentages : P1 = code propre (hors code tiers embarqué, traductions Qt, code généré) ; P2 = delta Kylin (debian/, correctifs, diff de l'orig.tar) ; P3 = fichiers de configuration et scripts. Plages : L3 90–100 %, L2 30–60 %, L1 5–15 %, X 0 %.
- Version livrée sans source correspondante = X ; un code Gitee d'une autre version ne sert qu'à un audit « par procuration », étiqueté comme tel.
- Un squelette `dh_make` sans binaire dans l'arbre est « absent-ou-vide » ; « reconditionnement-binaire » est réservé aux arbres contenant des binaires précompilés.
- PROBABLE est réservé aux indices tirés d'un fichier cité ; les analogies passent en NON COUVERT.
- Les constats négatifs sur les écoutes réseau valent « CONSTATÉ sur les indices de l'extracteur ; NON COUVERT au-delà » (l'extracteur ne reconnaît ni `g_dbus_server_new_sync` ni le gRPC Python).
- Les constats dépassant la Phase 0 (sémantique du code, recherche de secrets) sont des **hypothèses de Phase 1**, non des findings.
